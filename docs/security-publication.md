# 公開前のセキュリティ確認

2026-10-12、今回のGitHub公開対象を点検しました。秘密の値を検査ログに出さない方針で、Git追跡対象と追加予定ファイルを確認しています。

## 確認結果

- APIキー、GitHubトークン、JWT、秘密鍵、ローカル実行用アクセストークンの既知パターンに該当する値は公開対象で検出されませんでした。パターン検査は未知の形式の秘密を完全検出する保証ではありません。
- `.env.local`、`.local-data/`（DB本体）、`reports/`、ログ、ブラウザのテスト生成物はgitignore対象で、追跡されていません。
- `.env.example` のAPIキーとアクセストークンは空欄です。
- 同梱した評価証跡はseed 42で生成した架空ECデータの質問・SQL・集計結果です。実顧客データ、個人の認証ファイル、接続用の秘密は含みません。
- `npm audit --omit=dev` は既知の脆弱性0件でした。この監査はアプリの安全性全体を証明するものではありません。
- 実AIはサーバー側で呼び出し、Claudeキーはブラウザへ渡しません。ChatGPT接続は公式CLIが既存ログインを使い、アプリ自身は認証ファイルを読みません。
- SQLはAST検証と読み取り専用DB権限を通し、書き込み・許可外テーブル・危険関数を拒否します。SQL修正にはSQLSTATEだけを返します。
- ローカルの画面サーバーとDB公開ポートは127.0.0.1に限定する構成です。

## 2026-10-16 追加の点検と修正

コードを実行しない静的なセキュリティレビュー（SQL検証、認証、リクエスト処理、プロンプトインジェクション、Codex連携、公開デモ、XSS、ヘッダー）を行いました。XSS、コマンドインジェクション、秘密情報の漏えい、公開デモからの実AI呼び出し・SQL実行の経路は見つかりませんでした。次の点を直しています。

| 重さ | 内容                                                                                                                                                                                                                        | 対応                                                                      |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| 中   | CTEの名前はクエリ全体で集めていたが、PostgreSQLは有効範囲で解決するため、`pg_roles` などと同名のCTEを範囲外で参照するとシステム表（ロール名・設定値など）を読めた（実AIモードでトークンを持つ利用者が明示的に指示した場合） | `pg_` で始まるCTE名を拒否。2通りの攻撃例をテストに追加                    |
| 中   | UNIONの枝の `SELECT … INTO` と `FOR UPDATE` が構文検証をすり抜けた（DB側の読み取り専用トランザクションと権限で実害はなし）                                                                                                  | 枝の中の `intoClause` / `lockingClause` も拒否。テストに追加              |
| 中   | 同時実行の上限が本文の読み込み後に数えられ、並列の要求で超えられた。例外時に数が戻らず全員が429になりうった                                                                                                                 | 検査と同時に枠を確保し、すべての終了経路で一度だけ戻す                    |
| 低   | セキュリティヘッダーがなく、`X-Powered-By` を返していた                                                                                                                                                                     | CSP・HSTS・Permissions-Policy・COOP・CORP・`X-Frame-Options: DENY` を追加 |
| 低   | `Content-Length` のない要求は本文を全部読んでから大きさを確かめていた                                                                                                                                                       | ストリームのまま読み、64KBを超えた時点で打ち切る                          |
| 低   | CSV出力の数式対策が先頭の文字を置き換えていたため、負の数の符号が消えた（公開デモの差額）                                                                                                                                   | 数値はそのまま出力し、数式に見える文字列だけ先頭に `'` を足す             |
| 低   | 1本のクエリが5秒の間に使えるメモリと一時ファイルに上限がなかった                                                                                                                                                            | 分析用ロールに `work_mem = 16MB`、`temp_file_limit = 100MB`               |
| 低   | 比較演算子を伴うサブクエリ（`x 演算子 ANY (SELECT …)`）の演算子を許可リストで確かめていなかった                                                                                                                             | 同じ許可リストで検査                                                      |
| 低   | アクセス用トークンの長さを確かめていなかった                                                                                                                                                                                | 24文字未満では実AIモードを動かさない                                      |

あわせて、Vercelの関数の実行時間（実AIモードの120秒）、CLIでのデプロイ時にローカルのDBやレポートを送らないための `.vercelignore` を追加し、公開資料から応募目的・想定単価の記述を外しました。

GitHub側では、Dependabotのアラートとセキュリティ更新、CodeQL（`security-extended`）、プルリクエストでの依存関係の審査、非公開の脆弱性報告を有効にし、GitHub Actionsを全アクションのコミット固定・GitHub製のみ・最小権限にしました。

残る制約：実AIモードを公開する場合の共有レート制限と費用上限、構文の許可方式の網羅（未知のノード種別を拒否する方式への移行）は未対応です。公開デモはAI呼び出しもSQL実行も行いません。

## 公開しているサンプル値

`.env.example`、Docker構成、DB初期化SQLには、架空ローカルDB用の既定ユーザー名・パスワードがあります。これらは秘密ではなく公開前提の開発用値です。**本番・共有環境で流用しないでください。** このMacの専用DBにも使っていますが、ループバック接続のローカル検証に限定しています。

## 公開ソースと公開サービスは別

GitHubへコードを公開する判断であり、実AIサービスをインターネットへ公開する許可・安全性評価ではありません。個人認証、組織ごとのアクセス制御、共有レート制限、監査ログ、秘密管理、データのクラウド送信方針は実導入時に別途必要です。実顧客データをこの検証環境へ投入しないでください。

コミットのメールはGitHubのnoreplyアドレスを使用します。2026-10-16、公開前の初期のコミットに残っていた作者の個人メールアドレスを、履歴を書き換えてnoreplyアドレスに置き換えました（ファイルの内容は変えていません）。
