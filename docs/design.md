# UI・UXの設計方針

2026-10-20に画面を「黒曜石（Obsidian）」の質感へ作り直しました。分析結果の数字とSQLを主役にするため、色と装飾を絞り、動きで「いま何が起きているか」を伝えます。

## デザイン

- **色**：ほぼ黒の背景（`#050506`）、白と灰の文字、差し色はライム1色（`#c8ff3c`）。差し色はSQLのキーワード、根拠番号、主ボタン、グラフにだけ使います。
- **線**：髪の毛ほどの細い枠線（高精細画面では0.5px）で面を区切り、影は奥行きに必要な所だけ。
- **文字**：日本語は同梱のNoto Sans JP、数字・SQL・ラベルは同梱のGeist Mono（等幅・桁がそろう数字）。
- **背景**：細い格子とノイズが、ゆっくり動きます（操作の邪魔にならない濃さ）。
- **アイコン**：lucide のアイコン集。
- 色・線・文字・動きの値はCSSの共通トークン（`app/globals.css` の `:root`）で管理します。ヒーロー右の画面図は装飾です（数値は載せていません）。

## 動き

| 場面       | 動き                                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------------------ |
| SQL        | 1文字ずつ打たれていき、点滅するカーソルが追います。全文は最初からDOMにあり、コピー・読み上げは常に全文 |
| グラフ     | 棒が下から伸び、折れ線が左から引かれます                                                               |
| 数字       | 0から実際の値までカウントし、最後は必ず正確な値で止まります                                            |
| カード・行 | ばねの曲線（CSS `linear()`）で少しずつずれて出てきます                                                 |
| ボタン     | 押すと縮み、離すとばねで戻ります。ホバーで矢印が進みます                                               |
| 進み具合   | 段階ごとの番号と回転する印、届いたSQLをその場で打ち込み表示                                            |

動きを減らす設定（`prefers-reduced-motion`）では、すべての動きを止め、最初から完成した状態で表示します。

## 画面の形

- ヘッダーは高さ80px。最初の画面（ヒーロー）は `100svh − 80px`（古いブラウザ向けに `100vh` も指定）で、見出し・説明・質問欄が必ず最初の画面に収まります。見出しの大きさは幅と高さの小さい方に合わせて縮むので、背の低い横向きスマホでも収まります。
- 広い画面ではヒーローを左右2列（左に質問、右にSQLの画面図）、背の高いスマホ・タブレットでは縦に並べます。4Kでは文字と列幅を大きくします。
- 回答は質問欄のすぐ下に出て、その下に記録の再生・質問例・データの定義が続きます。

## 操作

- 初回は質問入力、記録の再生4シナリオ、質問例4つ。分析結果へフォーカスを移し、スクロールします。
- 入力欄は文書内に置き、結果・質問例・キーボードフォーカスを覆いません。
- 通信が失敗しても入力を残し、再試行できます。処理中は二重送信を防ぎ、停止できます。
- 新しい分析で結果と会話をリセットし、質問欄へフォーカスします。
- 集計表・SQL・実行情報は段階的に開きます。集計表はキーボードでもスクロールできます。
- SQLコピーの成功表示は操作した結果だけに出し、クリップボードを使えないときは説明します。
- 固定回答・記録の再生・実AIを画面上で区別して表示します。

## アクセシビリティと検証

可視ラベル、スキップリンク、明確なフォーカスリング、44px以上の主要操作、動きを減らす設定への対応を入れています。

自動テスト（Chromium・WebKit）で次を確かめています。

- 25の画面サイズ（280×653の折りたたみスマホ〜3840×2160、横向きスマホ4種を含む）で、横スクロール0、文字の欠け0、重なり0、ヘッダー80px、ヒーローの中身が最初の画面に収まる（`e2e/viewports.spec.ts`）。
- 通信失敗からの再試行、結果へのフォーカス、低モーション設定。
- axeのWCAG 2.1 A・AA関連ルールで、初期画面・表とSQLを開いた結果画面・記録の再生・会話の画面の違反0件。
